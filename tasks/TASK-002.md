# TASK-002｜GPON 要求与清单对齐

## 基准与交付目标

从 `task-001-frozen`（`059b46774cdab9d790ea21e04edbf22c492cef4a`）继续，复用 TASK-001 证据基础和已存在的合成原型。范围是 GPON 要求和声明的来源、提取、配置及工程范围对齐。TASK-003/004 的规则、Agent 与人审原型继续复用，正式业务核验按相应任务另行授权。

[PRD](../docs/PRD.md) 的 P03–P06、[CONTRACTS](../docs/CONTRACTS.md) §2–4、[ARCHITECTURE](../docs/ARCHITECTURE.md) §3–5 约束实施。设备类别、厂家型号、配置变体、需求槽位、站点组和合同范围分别记录。接口数量、设备数量及其它待核验值要保留其字段角色与计数口径。候选匹配不能拿待核验端口数或待核验数量当作提前过滤条件。

## 阶段与验收

| 阶段 | 内容 | 最低验收 |
|---|---|---|
| A | 字段契约矩阵和评测基础 | 冻结基线可测；现有逻辑种子、DATA-R1 合成开发数据以及原型使用清晰且不同的分母；字段、证据、配对、未知和信任门分别评分。交付工具、实测结果、失败诊断与后续数据接入约定。 |
| B | 清单映射与原始行列回查 | 能独立预览和确认列映射，区分公式/缓存、空行、错误与重复。以真实文件格式的合成 CSV/XLSX 验证源行列往返。 |
| C | 要求候选提取与逐字段来源 | 在明确支持的表格和条款范围中，用独立答案验证原值、比较符、单位、效力、条件和来源。保留未确认的跨页表头、脚注及字形风险。 |
| D | 实体、配置、范围及需求槽位对齐 | 口径、身份、配置、工程范围及槽位分别提供匹配依据，保留一对多和未确定关系；待核验值有差异仍可送核验。 |
| E | 阶段综合验收 | 运行独立 E2E Gold 和边界回归，分别报告可判、拒判和失败。区分开发样本、独立合成样本及授权真实样本。 |

TASK-002-COMPLETE 实施了 A 定向收尾和 B/C/D 的最小流程。E 的开发回归已执行，独立合成 Gold 与正式工程验收待完成。R1/R1.1 信任门继续生效。未获得可审计的字段核验和实体确认时，工作流不得因条件化逻辑参考而产出确定结论。独立数据集的接入按 [评测说明](../docs/TASK-002A-evaluation.md) 进行。DATA-R1 已参与研发和审查，列为开发回归数据。

### A-R2 实施范围

- WP1 保留字段原值、规范值、值状态及原有证据和风险。只有明确字段证据才表达不适用或不限定。
- WP2 产出逐维候选依据、未决维度、阻断和关系拓扑。明确冲突不入正召回，型号差异可保留候选但仍未确认。召回不依据待核验字段相等，也不按字符串推断工程范围覆盖。
- WP3 按量的角色配对设备数、接口配置、单台端口数或显式技术属性。用户须选取候选，现有来源和人工核验门维持不变。
- WP4 按未审核开发回归口径分别度量明确边、歧义边、字段的三个分母、信任门与对象级阶段匹配。保留 413a051 原始基线与 Gold。报告残余缺口，尚未进入阶段 E。

## TASK-002-COMPLETE 实现与边界

- B：CSV/XLSX 映射、原始行列与工作表可查。声明设备数、显式接口配置和独立技术值可共存。公式和错误单元格保持原值与未知状态。Web 可查看映射并记录自述。
- C：复用 MinerU 解析运行和 Evidence。支持具备显式原表头的规则 HTML、带本产物指针的结构化单元格和有限明确正文。要求字段可回查来源、物理页、块内数据行、列号与原始表头。拆列比较符和数值按同一行派生表达式。EXP-03 实验别名投影以及未确认续表不产出表格候选。
- D：保留所有合理候选、拓扑和字段配对。型号不明和站点覆盖未证分别处理。通用 Ethernet 或 port_count 缺设备接口类型时不推断 GE。绑定和字段仍由信任门控制。
- 最小流程：`ira verify offline` 和 Web 使用相同 Workflow。明确选择配对后可请求附假设的值运算。正式处置仍由原信任门控制。参见[离线复验](../docs/TASK-002-offline.md)。
- 待验：独立 E2E Gold、真实工业语义、可信字段核验、结构化扩展的跨解析器覆盖、复杂续表、脚注归属、更多条件和版本规则。TASK-003 与 SEC-001 仍未启动。

DATA-R1 仅作开发回归。禁止使用 Gold 填充业务事实、用字段自述升级信任或向外部服务发送未经授权的资料。
