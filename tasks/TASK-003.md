# TASK-003｜可信人工核验与规则处置

## 路径

从 TASK-002 草案展开「候选依据与未决维度」，选择「核对这组候选」。工作台提供 PDF 物理页、原始清单行与映射字段。对同一个候选分别保存逐字段核验、来源核对、实体绑定及适用性。每次保存需填写本机操作者标识、核验说明和结论。字段页保留原值、规范值、位置与派生依据。

「按当前记录重算」显示未通过的门、条件化计算和正式规则结果。正式计算以声明值和已核对的约束为输入，结果用于工程人工复核。结论包含满足、不满足、不适用与待复核。可在运行详情展开快照，也可返回配对查看核验历史。输入有变更时，旧运行标明失效，仍可查历史快照。

## 输入和信任边界

- 候选选择、实体确认、字段核验、来源核对和适用性独立。用户可确认多个字段，但需要逐项选入该条核验记录。同一配对的最新结论可否决前次记录。
- 使用本机单用户信任边界。工作台保存动作检查同源、CSRF、服务端签发的表单签名、快照、历史前序和核验备注。应用操作者标识由本机用户输入。具有本机控制权的进程与用户共享该信任边界。
- 现有核验入口、自述勾选及 Agent 补查无法写入人工核验记录。原始 PDF、解析资产及清单校验失败时，核验阻断。实体绑定自述与 ParseRun 的 `binding_state` 各有用途。
- 恢复表保留原 PDF、派生定位及原生追溯信息，人工来源确认仅适用于所查配对。未确认的续表及脚注归属、型号冲突、站点覆盖和计数口径仍阻断。正式条件比较要求可核查的范围、版本和条件输入。认定明确不适用还需要可观察的相反工况或来源明确排除证据。
- 要求与要求的 `ConstraintRelation` 仍走独立的现有比较入口。正式处置、满足性、条件化计算和字段状态各自记录。强制条款与可信程度共同决定能否产生问题。参考性或信息性条款保留信息性处置。
- 导入新解析运行、修订或新清单映射后重新核验。已登记的同文档修订变动会保守使旧快照失效，版本优先级和补遗覆盖需额外证据。未登记逻辑文档关系时，系统不能自行关联新旧文档。

## CLI、离线及迁移

本机工作台写入人工核验记录。CLI 可读取、导出，并显式使用已有记录重算。选择文件仅传候选 ID 与声明行 ID，数据库按当前快照取人工记录。

```powershell
uv run --locked ira verify run $draftId --reviewer '本机操作者' `
  --confirmations $selections --conditional-preview --use-human-reviews
uv run --locked ira verify show $runId
```

`ira verify offline` 保持默认候选模式，也支持 `--use-human-reviews` 在同一数据库和输入快照重算。概要仅含统计和状态。原始输入、数据库和详情按授权留在本机。

Alembic `0003_human_verification` 在应用打开 SQLite 时增加 `human_verification_records`。原有表和对象不改写。保留旧工作台核验、人工处置及历史信任门。迁移不需安装新依赖。
